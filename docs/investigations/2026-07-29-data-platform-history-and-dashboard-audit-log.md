## 最初目标与判定口径

最初目标固定为：

> 研究 GitHub 项目的数据源、字段和采集机制，在 one-trading 内重写成自己的 Provider、同步任务、Parquet 数据集和本地 API，最终形成可持续更新的数据工具台。上游项目只作为数据来源、字段和采集机制情报，不作为 one-trading 的运行时依赖。

每轮工作按下面五类判定，避免以后把“写了很多代码”误当成“目标已完成”：

- `直接对齐`：产出可验证的 Provider、同步任务、Parquet 或本地查询路径。
- `研究对齐`：形成数据来源、字段、单位、采集机制或准入结论，但尚未交付数据。
- `基础设施必要`：解决当前最小数据链不可绕过的公共问题，且改动保持最小。
- `范围扩张/过度设计`：建设 Catalog、Agent、控制器、journal、guard、恢复链或生产晋级，但没有增加可消费数据。
- `授权冲突`：在用户只要求审计、规划或候选验证时，发生生产进程、正式数据、push、部署或其他越界动作。
